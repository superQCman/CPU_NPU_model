## 一、三级存储 (dlrm_msprof_mtrain.py)

### 1.1 运行方式

通过 `dist_dlrm.sh` 启动 8 卡 NPU 分布式推理：

```bash
bash dist_dlrm.sh
```

等价于：

```bash
torchrun --nproc_per_node=8 dlrm_msprof.py \
    --use-mtrain \
    --use-gpu \
    --inference-only \
    --mini-batch-size=32 \
    --arch-embedding-size="100000-100000-100000-100000-100000-100000-100000-100000" \
    --arch-sparse-feature-size=64000 \
    --arch-mlp-bot="600-500-400-300-64000" \
    --arch-mlp-top="640-600-500-320-1" \
    --data-size=320 \
    --dist-backend="hccl" \
    --num-indices-per-lookup-fixed=True \
    --num-indices-per-lookup=100 \
    --num-workers=8 \
    --profiler-path="./profiling_test_17"
```

`dlrm_msprof_mtrain.py` 在 import 时将 `DLRM_Net.create_emb` 替换为 `MTrainSEmbeddingBag`，`--use-mtrain` 触发三级存储逻辑，其余参数透传给 `dlrm_msprof.py`。

### 1.2 可选参数

**MTrainS 专用：**

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--use-mtrain` | 关闭 | 启用三级存储 |
| `--hbm-ratio` | 0.01 | HBM 容量占 Embedding 总行数的比例 |
| `--dram-cache-ratio` | 0.05 | DRAM 缓存容量占 Embedding 总行数的比例 |

**继承自 dlrm_msprof.py 的关键参数：**

| 参数 | 含义 |
|------|------|
| `--mini-batch-size` | 每卡 batch 大小 |
| `--inference-only` | 推理模式（不训练） |
| `--arch-embedding-size` | 各 Embedding Table 行数，`-` 分隔 |
| `--arch-sparse-feature-size` | Embedding 向量维度 |
| `--arch-mlp-bot` | 底部 MLP 各层宽度，`-` 分隔 |
| `--arch-mlp-top` | 顶部 MLP 各层宽度，`-` 分隔 |
| `--data-size` | 数据集样本数 |
| `--use-gpu` | 使用 NPU/GPU |
| `--dist-backend` | 分布式后端（NPU 用 `hccl`） |
| `--num-workers` | DataLoader 进程数 |
| `--profiler-path` | profiling 输出目录 |

### 1.3 示例输出

输出文件：`memory_access_timings.log`

格式如下：

```
# Timestamp: 2026-05-29 18:02:40
[Metrics] step=10 HBM_hit=1.0% DRAM_hit=4.7% SSD_hit=94.3%
  HBM -> NPU cache : 14.707 ms/step, 78.1 MB total, 0.5 GB/s
  DRAM -> CPU cache: 30.782 ms/step, 365.3 MB total, 1.2 GB/s
  SSD -> DRAM      : 2044.258 ms/step, 7353.3 MB total, 0.4 GB/s
  DRAM -> HBM      : 4.248 ms/step, 20.0 MB total, 0.5 GB/s
  TOTAL wall time: 2115.063 ms/step
```

程序将输出各段访存路径的时间，以及总时间。

## 二、两级存储 (two_cache.py)

### 2.1 运行方式

```bash
python dlrm_s_pytorch.py \
    --inference-only \
    --arch-embedding-size="1000-1000-1000-1000-1000-1000-1000-1000" \
    --arch-sparse-feature-size=64000 \
    --mini-batch-size=32 \
    --data-size=320 \
    --arch-mlp-bot="600-500-400-300-64000" \
    --arch-mlp-top="640-600-500-32" \
    --use-two-level-embedding \
    --dram-cache-ratio=0.3
```

`dlrm_s_pytorch.py` 在 `create_emb` 中检测 `--use-two-level-embedding` 标志，启用时用 `TwoLevelEmbedding` 替换原始的 `nn.EmbeddingBag`。

### 2.2 可选参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--use-two-level-embedding` | 关闭 | 启用两级存储 |
| `--dram-cache-ratio` | 0.05 | DRAM 缓存容量占 Embedding 总行数的比例 |

其余参数（`--arch-embedding-size`、`--mini-batch-size` 等）与 `dlrm_s_pytorch.py` 原生参数一致。

### 2.3 示例输出

输出文件：`memory_access_timings.log`

格式如下：

```
=== Memory Access Timings ===
SSD_to_DRAM: 0.223752 seconds, Data size: 44288000 bytes
DRAM_to_CPU: 0.000035 seconds, Data size: 768000 bytes
```

## 三、重用距离预测 (reuse_distance.py)

### 3.1 运行方式

**合成 Trace（Zipfian 分布）：**

```bash
python tier_prediction/reuse_distance.py \
    --num-embeddings 100000 \
    --trace-length 500000 \
    --zipf-alpha 1.0 \
    --th-hbm 100 \
    --th-dram 1000
```

**如果使用真实 Trace 文件：**

```bash
python tier_prediction/reuse_distance.py \
    --trace-file ./data/my_trace.txt \
    --th-hbm 50 \
    --th-dram 500
```

`trace.txt` 每行一个整数索引，记录 Embedding 的访问顺序。

**容量模式（按 hbm_rows/dram_rows 填满）：**

```bash
python tier_prediction/reuse_distance.py \
    --num-embeddings 100000 \
    --trace-length 500000 \
    --hbm-rows 1000 \
    --dram-rows 10000
```

**输出 JSON 供 memory_model.py 使用：**

```bash
python tier_prediction/reuse_distance.py \
    --num-embeddings 100000 \
    --trace-length 500000 \
    --hbm-rows 1000 --dram-rows 10000 \
    --output-json reuse_result.json
```

### 3.2 可选参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--num-embeddings` | 100000 | 唯一 Embedding 数量（合成模式） |
| `--trace-length` | 500000 | 访问序列长度（合成模式） |
| `--zipf-alpha` | 1.0 | Zipf 分布偏度，越大热点越集中 |
| `--trace-file` | — | 真实 trace 文件路径 |
| `--th-hbm` | 100 | HBM 阈值：平均重用距离 ≤ N → HBM |
| `--th-dram` | 1000 | DRAM 阈值：平均重用距离 ≤ N → DRAM |
| `--hbm-rows` | — | [容量模式] HBM 行数，按平均 RD 升序取 top-K |
| `--dram-rows` | — | [容量模式] DRAM 行数，取 HBM 之后的 K 行 |
| `--output-json` | — | 输出 JSON 路径（供 memory_model.py） |
| `--include-details` | 关 | JSON 含每个 embedding 的 tier / 平均 RD |
| `--fast-hit-rates` | 关 | 用访问频次聚合算命中率（O(U) 而非 O(N)） |
| `--seed` | 42 | 随机种子（合成模式） |

### 3.3 示例输出

输出格式如下：

```
=================================================================
  Reuse Distance Storage Tier Prediction
=================================================================
  Total accesses:              500,000
  Unique embeddings:            61,965
  Thresholds:             HBM ≤ 100,  DRAM ≤ 1000
=================================================================

  Tier Distribution:
    HBM  :         17 embeddings (  0.0%)  avg RD=57.3
    DRAM :        233 embeddings (  0.4%)  avg RD=584.4
    SSD  :     61,715 embeddings ( 99.6%)  avg RD=23609.3

  Hit Rates (simulated):
    HBM  :  25.07%  ██████████
    DRAM :  21.59%  ████████
    SSD  :  53.34%  █████████████████████
=================================================================
```
输出预测的各级存储中embedding数量，以及预测的hit率

## 四、访存时间模型 (memory_model.py)

### 4.1 运行方式

```bash
# 直接给定各层命中次数预测
python query/memory_model.py --hbm-hits 800 --dram-hits 150 --ssd-misses 50 --dim 64000

# 从日志标定 α/BW
python query/memory_model.py --calibrate memory_access_timings.log

# 从 reuse_distance 的 JSON 结果预测
python query/memory_model.py --from-reuse reuse_result.json --total-accesses 3200 --dim 64000 --breakdown
```

### 4.2 输入参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--hbm-hits` / `--dram-hits` / `--ssd-misses` | 0 | 各层命中次数（直接计数模式） |
| `--migrate-count` | 0 | 迁移行数（DRAM→HBM） |
| `--dim` | 64000 | Embedding 维度 |
| `--dtype` | float32 | 元素精度（float32/float16/bf16） |
| `--calibrate` | — | 从日志标定 α/BW |
| `--from-reuse` | — | 读 reuse_distance 的 JSON 结果 |
| `--total-accesses` | 0 | 单次推理总查询量 K（=B·k·T） |
| `--migration-ratio` | 0.01 | HBM 迁移比例 η |
| `--breakdown` | 关 | 输出 latency vs bandwidth 分解 |

### 4.3 输出

打印四段通路（HBM→NPU / DRAM→CPU / SSD→DRAM / DRAM→HBM）耗时汇总表（α、BW、Time(ms)、%Total）+ `TOTAL`，以及平均每 lookup 延迟、latency/bandwidth 占比。

## 五、迁移带宽测量 (measure_migration_bw.py)

### 5.1 运行方式

```bash
# 先建 SSD 测试文件（一次即可）
fallocate -l 20G ~/testfile

# 扫描多档大小，拟合 T = α + S/BW
python migration/measure_migration_bw.py --sizes 1 2 4 8 16 32 64 128 256 512 1024 --repeat 5
```

### 5.2 输入参数

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `--sizes` | 1 10 100 512 | 扫描的数据大小（MB） |
| `--repeat` | 3 | 每个大小重复次数 |
| `--ssd-file` | ~/testfile | fio 随机读测试文件 |
| `--ssd-runtime` | 15 | 每档大小 fio 运行秒数 |

### 5.3 输出

`migration_bw_result.json`：三条迁移链路（HBM→DRAM / DRAM→HBM / SSD→DRAM）的 BW、α、R²、扫描点。

## 六、写回建模 (measure_update_bw.py / update_model.py)

### 6.1 测写回链路带宽

```bash
# 单行随机写（QD=1）
python update/measure_update_bw.py --sizes 1 2 4 8 16 32 64 128 256 512 1024

# 脏行批量刷回（高 QD）
python update/measure_update_bw.py --sizes 1 2 4 8 16 32 64 128 256 512 1024 --ssd-qd 32
```

输入：`--sizes`、`--repeat`、`--dim`、`--byte-per-elem`、`--ssd-file`、`--ssd-runtime`、`--ssd-qd`（1=单行随机写，8/16/32=批量刷回）。

输出：`update_bw_result.json`：两条写回链路（NPU→DRAM / DRAM→SSD）的 BW、α、R²、扫描点。

### 6.2 预测写回时间

```bash
python update/update_model.py --n-dram 3000 --n-ssd 700 --dim 64000 --result update_bw_result.json
```

输入：`--n-dram` / `--n-ssd`（本步写回/刷回的行数，已去重）、`--dim`、`--dtype`、`--result`（标定 JSON）、`--n-batches-dram` / `--n-batches-ssd`（打包成的拷贝批次数，默认 1）。

输出：各段写回时间（NPU→DRAM、DRAM→SSD）+ `TOTAL`（ms）。α 按拷贝批次计，不按行计。
